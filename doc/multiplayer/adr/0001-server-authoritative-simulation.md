# ADR-0001：服务器权威与单模拟线程

- 状态：已接受
- 日期：2026-07-12
- 关联计划：第 5、6、9、19、20 节

## 背景

CDDA 的世界对象、缓存、随机数和大量静态状态按单进程、单活动 avatar 设计。当前 `game::do_turn()` 在同一调用链中推进角色、地图、怪物、NPC、天气、声音和 UI。尝试让多个客户端分别计算结果，或让多个线程同时调用游戏规则，会产生不可控的状态分歧、数据竞争和存档损坏。

客户端仍需要保留本地输入、触控、tileset、字体、语言、面板、音效包和窗口布局，否则 Android 与 Windows 客户端无法维持现有体验。

## 决策

多人模式采用服务器权威模型：

- 服务器拥有世界时间、RNG、地图、实体、角色、moves、活动、库存、行动验证、结果和 canonical save。
- 客户端只拥有物理输入映射、本地 UI 状态和表现配置；客户端状态镜像为只读缓存。
- 网络上传输语义命令和服务器生成的结果，不接受客户端计算的位置、伤害、命中、消耗、moves、可见性或 RNG 结果。
- 只有模拟线程可以读取和修改 live CDDA 世界对象。
- 网络和压缩线程只处理有界队列中的不可变 DTO。快照必须由模拟线程在安全点构建后再交给工作线程。
- 单人模式与多人模式调用同一组规则 executor，避免维护两套玩法实现。
- 保存只在回合屏障后的静止点开始，保存期间不并发执行世界命令。

## 替代方案

- 跨平台 deterministic lockstep：拒绝。平台、编译器、浮点、容器顺序、mod 和 RNG 调用顺序都使其不可维护。
- 客户端权威或结果合并：拒绝。无法可靠验证位置、库存、战斗、制作和隐藏信息。
- 每名玩家一个模拟线程：拒绝。现有全局访问、缓存和静态容器不具备线程安全性。
- 多进程共享 save 目录：拒绝。没有事务、锁或实体唯一性保证，会破坏存档。

## 后果

- 服务器是性能、可用性和持久化的唯一关键点，需要结构化日志、备份和恢复机制。
- 客户端不能离线推进 canonical 人物，也不做首版预测和回滚。
- 规则/UI 解耦是远程动作覆盖的必要工作，服务器执行路径必须禁止阻塞 UI。
- 线程边界必须通过断言和测试固化；网络层不得持有 `game`、`map`、`Character` 等 live object 指针。

## 验证要求

- ThreadSanitizer 或等价测试证明网络/压缩工作线程不访问 live simulation object。
- loopback 集成测试证明重复命令最多执行一次，客户端伪造结果不会改变服务器状态。
- 单人动作回归测试证明 executor 提取后旧行为和旧存档兼容性不退化。
- 保存与故障注入测试证明命令执行和 generation 提交不会交错产生半完成状态。
